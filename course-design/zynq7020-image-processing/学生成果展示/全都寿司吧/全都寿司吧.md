# 全都寿司吧

FPGA 图像处理综合扩展设计 — 基于 ZYNQ7020 的 720P 图像显示与多算法边缘检测系统

核心扩展：完成 720P 分辨率升级适配，集成三种图像预处理策略，实现 Sobel、Prewitt、Laplacian 三种经典边缘检测算法的实时切换与显示。

开发环境：Xilinx Vivado + Xilinx SDK/Vitis；硬件平台：黑金 ZYNQ7020 + HDMI + USB 串口

## 综合扩展任务选择与理由

基于实验五 sobel_05_pc_control_display 工程，围绕图像输入、图像显示和 PL 图像处理能力三个方向增强：

| 扩展任务 | 核心实现内容 | 核心价值 |
| --- | --- | --- |
| 任务 01 | 分辨率从标清提升至 1280×720 (720P)，重构数据传输与缓存逻辑 | 大幅提高清晰度与细节还原度 |
| 任务 02 | 新增 Stretch/Letterbox/Crop 三种自适应图像预处理策略 | 解决不同输入源尺寸不匹配问题 |
| 任务 03 | PL 端新增 Prewitt 和 Laplacian 算法，构建多算法处理单元 | 丰富算法库，实现硬件级实时切换 |

扩展后系统链路：任意输入图像 → PC 端归一化为 720P 标准流 → FPGA 执行硬件级图像增强 → HDMI 实时输出。

## 系统总体架构

扩展前 (轻量基础版)：PC → UART → PS 写 AXI BRAM (128×72) → PL 直读 BRAM → 单一 Sobel → HDMI

扩展后 (高性能完整版)：PC 预处理 1280×720 RGB888 → UART → PS 写 DDR Framebuffer → AXI VDMA 输出 AXI4-Stream → PL 多模式切换 (Original/Gray/Edge/Overlay) → 720P HDMI

核心演进：存储从 BRAM 升级为 DDR；显示由 PL 直读改为 VDMA 流式传输；算法从单一 Sobel 扩展为 Sobel + Prewitt + Laplacian。

| 关键对比项 | 扩展前 | 扩展后 |
| --- | --- | --- |
| 分辨率与存储 | 128×72，AXI BRAM 有限存储 | 1280×720，DDR framebuffer 双帧缓存 |

## 扩展1：1280×720 分辨率升级

720P RGB888 单帧数据量 = 1280×720×3 = 2,764,800 Byte，远超片上 BRAM 极限。选用 DDR 作为大容量帧缓冲，通过 AXI VDMA 硬核控制器实现 DDR 数据到 AXI4-Stream 视频流的高效转换，确保 HDMI 实时稳定显示。

关键配置：IMG_WIDTH=1280, IMG_HEIGHT=720, BYTES_PER_PIXEL=3, FRAME_BYTES=1280×720×3。VDMA 读取配置：VertSizeInput=720, HoriSizeInput=1280×3, Stride=1280×3。

## 扩展2：任意尺寸图像预处理

三种策略将输入统一转换为 1280×720 后发送给 FPGA：

| 策略 | 核心处理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| Stretch (拉伸) | 忽略宽高比，强制拉伸至 1280×720 | 速度快，画面铺满 | 可能产生比例形变 |
| Letterbox (补边) | 保持比例缩放，不足区域填黑边 | 图像不变形 | 屏幕出现黑边 |
| Crop (裁剪) | 保持比例缩放后中心裁剪 | 铺满且不变形 | 可能损失边缘信息 |

预处理放在 PC 端：更灵活，减少 FPGA 资源消耗，让 FPGA 专注核心算法加速。

## 扩展3：三算法与 PL 硬件结构

| 算法 | 类型 | 特点 |
| --- | --- | --- |
| Sobel | 一阶微分/梯度 | 加权平均，抑制噪声，边缘响应强 |
| Prewitt | 一阶微分 | 无加权差分，结构对称，资源消耗略低于 Sobel |
| Laplacian | 二阶微分 | 对灰度突变敏感，无需计算梯度方向，硬件结构极简 |

Prewitt: Gx=-p00+p02-p10+p12-p20+p22, Gy=-p00-p01-p02+p20+p21+p22

Laplacian: Kernel=[0,-1,0; -1,4,-1; 0,-1,0], lap=4*p11-p01-p10-p12-p21

PL 并行流水线：VDMA RGB 视频流 → rgb_to_gray → 并行送入 Sobel/Prewitt/Laplacian 三个核心模块 → algorithm_select MUX (组合逻辑零延迟切换) → HDMI 显示

Verilog 关键逻辑：assign algorithm_sel = control[19:17]; assign out = (sel==LAP)?lap:(sel==PRE)?prew:sobel;

## 实验结果

完成上板验证，可正常显示 1280×720 HDMI 图像，支持三种边缘检测算法切换：

| 算法 | 实测效果 | 技术特点 |
| --- | --- | --- |
| Sobel | 边缘线条明显，轮廓完整，噪声抑制好 | 一阶差分，梯度响应强 |
| Prewitt | 与 Sobel 相近，适合做基准对比 | 结构简单，无需加权 |
| Laplacian | 边缘更细，对灰度突变区域响应灵敏 | 二阶微分，细节丰富 |

实验中三种算法统一采用同一张 720P 标准测试图，使用完全一致的显示链路和阈值参数。算法模式的实时切换由上位机下发指令控制 PL 端逻辑完成，无需重新编译 Bitstream。

## 遇到的问题与解决方法

| 问题 | 成因 | 解决方案 |
| --- | --- | --- |
| 720P 图像过大无法缓存 | 单帧 ~2.64 MiB，BRAM 不足 | 改用 DDR + AXI VDMA 高速传输 |
| HDMI 显示上下半幅交换/错位 | PS/PL 读写顺序与帧同步时序不一致 | 统一 Row-major 扫描，修正 VDMA tuser 信号 |
| VDMA 帧起始与 HDMI 不同步 | 时钟域未严格对齐 | 仅在 HDMI 有效区左上角坐标时接受新帧起始 |
| PL Implementation 资源压力大 | 720P 链路 + 多算法叠加 | 流式处理架构，复用灰度转换与显示逻辑 |
| 多算法切换控制复杂 | 多种算法需统一管理 | 指定 control[19:17] 作为 algorithm_select 字段 |

## 总结

基于实验五完成三个综合扩展：
- 720P 分辨率全链路升级（重构数据通路，适配 1280×720 输入规格）
- 多模式图像预处理策略（Stretch/Letterbox/Crop 三种显示适配）
- PL 端边缘检测算法库（Sobel/Prewitt/Laplacian 硬件化实现，寄存器动态配置与实时切换）
- 上位机全参数控制中心（模式选择、阈值调节、OSD 叠加、算法切换）
- 系统级上板验证闭环（HDMI 输出稳定无失真，算法切换响应迅速）
